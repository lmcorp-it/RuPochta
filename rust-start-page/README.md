# RuPochta — стартовая страница на Rust (сборка V2)

Стартовая страница (**вход + регистрация**) для **рупочта.рф**, реализованная на **Rust / Axum**.
Это полноценная сборка дизайна V2: интерактивная страница входа/регистрации + бесконечный холст с
дизайн-системой, оба отдаются одним Rust-сервером, формы ходят в реальные API-эндпоинты.

Внешний вид и структура соответствуют дизайну `V2 RuPochta Вход и регистрация-*` и повторяют логику
оригинального сервиса из репозитория [github.com/lmcorp-it/RuPochta](https://github.com/lmcorp-it/RuPochta)
(FastAPI → Rust).

## Маршруты

| Метод | Путь | Что делает |
|---|---|---|
| GET | `/` | Стартовая страница: вход + регистрация (V2, тёмная премиальная подача, оба 3D-ассета встроены base64) |
| GET | `/canvas` | Бесконечный холст: контекст проекта, дизайн-система, макеты (дизайн-пакет V2) |
| GET | `/health`, `/ready` | Проверки живости, как в оригинальном сервисе |
| GET | `/api/signup/config` | Настройки регистрации (включена ли, домен, мин. длина пароля); страница сама решает, показывать ли CTA «Завести почту» |
| POST | `/api/signup` | Создание ящика: серверная валидация имени (3–30, латиница/цифры/точка/дефис/подчёркивание), длины пароля, совпадения паролей |
| POST | `/api/login` | Вход: серверная валидация полей |

Страница умеет работать и без сервера: при открытии файлом `static/index.html` формы переходят
в демо-режим; под Rust-сервером — в реальные API-эндпоинты (мост автоматически определяется
через `fetch('/api/signup/config')`).

## Запуск

Нужен Rust (rustc ≥ 1.75). Установка: https://rustup.rs

```bash
cargo run --release
# откройте http://127.0.0.1:8080  (страница)
#        http://127.0.0.1:8080/canvas  (дизайн-холст)
```

## Конфигурация (переменные окружения)

| Переменная | По умолчанию | Описание |
|---|---|---|
| `RUPOCHTA_BIND` | `0.0.0.0:8080` | адрес прослушивания |
| `RUPOCHTA_DOMAIN` | `example.com` | домен почтовых ящиков |
| `RUPOCHTA_SIGNUP_ENABLED` | `1` | разрешить регистрацию (`1`/`0`) |
| `RUPOCHTA_MIN_PASSWORD` | `10` | минимальная длина пароля |

Пример:

```bash
RUPOCHTA_DOMAIN=rupochta.ru RUPOCHTA_SIGNUP_ENABLED=1 cargo run --release
```

## Тесты

```bash
cargo test
```

Покрыты: валидация имени ящика, правила пароля, эндпоинты `/health`, `/`, `/canvas`,
`/api/signup` (успех, короткий пароль, несовпадение), `/api/login`.

## Структура

```
rupochta-rust/
├── Cargo.toml          # зависимости: axum, tokio, serde, tower-http
├── src/main.rs         # сервер, API, валидация, тесты
└── static/
    ├── index.html      # страница входа и регистрации (V2, с встроенными ассетами)
    └── canvas.html     # бесконечный холст — дизайн-пакет (V2)
```

## Как менять

- **Тексты и домен по умолчанию** — в `static/index.html` (строки `@example.com`, подписи форм);
  домен при запуске берётся из `RUPOCHTA_DOMAIN`.
- **Цвета и шрифты** — CSS-переменные в `<style>` в начале `static/index.html`
  (`--cobalt`, `--red`, `--cyan`, `--font-display` и т.д.).
- **Изображения** — встроены в HTML как base64 (ассеты `hero-1.png`/`hero-2.png`, оптимизированы
  в WebP). Замена: конвертируйте новое изображение в WebP, закодируйте в base64 и замените
  `data:image/webp;base64,...` в `static/index.html`.
- **Правила валидации** — `validate_login_name` / `validate_password` в `src/main.rs` (сервер)
  и те же правила в `<script>` в `static/index.html` (клиент).
- **Дизайн-система** — `static/canvas.html`, ряды «Контекст / Дизайн-система / Макеты».
- **Порт и поведение** — переменные окружения из таблицы выше.

## Качество

- **Состояния**: кнопки default/hover/active/disabled, спиннер при отправке, ошибки красным под
  полями (`aria-invalid`), успех («Ящик создан»), пустые/невалидные поля.
- **Форма**: лейблы над полями (не placeholder-only), показать/скрыть пароль, «Запомнить вход»,
  «Не помню пароль», проверка совпадения паролей, минимальная длина.
- **Доступность**: sr-only, aria-describedby, focus-visible (кобальтовое кольцо), prefers-reduced-motion.
- **Адаптив**: десктоп 1536×1024, планшет, мобильный 390×844 — единая страница перестраивается;
  на мобильном левая панель с ассетами скрывается.
- **Ассеты локальные**: оба изображения встроены в файл, внешних зависимостей нет — открывается
  даже без сети.
- **Безопасность**: пароли не логируются, в ответах API нет секретов (демо-режим).

## Ограничения

Демо-режим: сервер валидирует формы и отвечает успехом, но реальные ящики/сессии не создаёт —
для этого нужен бэкенд IMAP/SMTP, как в оригинальном репозитории (Python/FastAPI).
Структура API повторяет его 1:1, так что интеграция с реальным бэкендом — замена обработчиков
`signup` / `login` на обращения к вашему почтовому серверу.

## Расположение в репозитории
Этот проект живёт в подпапке ust-start-page/ репозитория RuPochta — отдельно от Python-бэкенда (FastAPI), чтобы не конфликтовать с его структурой (static/, tests/ и т.д.).
Запуск из подпапки: cd rust-start-page && cargo run --release.
