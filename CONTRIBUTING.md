# Как участвовать в разработке RuПочта

Проект открыт для всех: правки в коде, тесты, дизайн, документация, переводы,
просто внятно описанный баг — всё это помогает. Опыта в почтовых протоколах не
требуется, большая часть задач — обычные Python и веб.

Пишите на русском или английском, как удобнее.

## Что можно взять прямо сейчас

- Задачи с меткой [`good first issue`](https://github.com/lmcorp-it/RuPochta/labels/good%20first%20issue)
  — маленькие и с описанным контекстом.
- [`help wanted`](https://github.com/lmcorp-it/RuPochta/labels/help%20wanted) —
  крупнее, но никто ими не занят.
- Своя идея — заведите issue и опишите её до того, как писать код: так меньше
  шансов, что работа пойдёт в стол.

## Среда разработки

Нужен Python 3.11+ и git. Почтовый сервер для запуска тестов **не нужен**.

### В браузере, без установки

[![Открыть в Codespaces](https://github.com/codespaces/badge.svg)](https://codespaces.new/lmcorp-it/RuPochta)

Codespace поднимается из [`.devcontainer/devcontainer.json`](.devcontainer/devcontainer.json):
Python 3.12, зависимости уже поставлены, переменные для разработки заданы,
порт 18400 пробрасывается приватной ссылкой. Достаточно выполнить

```bash
python -m uvicorn rupochta_server:app --reload --port 18400
```

и открыть проброшенный порт. Работает с любого устройства, включая планшет.

Тот же файл понимают VS Code с расширением Dev Containers и JetBrains Gateway —
можно поднять окружение локально в Docker, ничего не настраивая руками.

Быстро поправить текст или разметку можно вообще без окружения: нажмите
<kbd>.</kbd> на странице репозитория — откроется веб-редактор `github.dev`.

### Локально

**Linux / macOS**

```bash
git clone https://github.com/lmcorp-it/RuPochta.git && cd RuPochta
python3 -m venv .venv && .venv/bin/pip install -r requirements.txt
.venv/bin/python -m unittest discover -s tests
```

**Windows (PowerShell)**

```powershell
git clone https://github.com/lmcorp-it/RuPochta.git; cd RuPochta
py -m venv .venv; .\.venv\Scripts\pip install -r requirements.txt
.\.venv\Scripts\python -m unittest discover -s tests
```

В WSL работает вариант для Linux. Дальше приложение поднимается одинаково:

```bash
WEBMAIL_DB=./dev.sqlite MAIL_ADMIN_KEY=dev WEBMAIL_SECRET_KEY=dev-secret \
  python -m uvicorn rupochta_server:app --reload --port 18400
```

Откройте `http://127.0.0.1:18400/` — экран входа и вся вёрстка доступны без
почтового сервера. `/health` отвечает всегда, `/ready` — только когда доступны
IMAP и SMTP.

Фронтенд — обычные HTML/CSS/JS в `static/`, сборки нет: правите файл, жмёте
Ctrl+F5. Docker-вариант описан в [README](README.md#docker).

## Правила, которых мы придерживаемся

1. **Одно изменение — один pull request.** Маленький PR ревьюится за день,
   большой висит неделями.
2. **Тесты обязательны для логики.** `tests/` — обычный `unittest`, без
   фреймворков и фикстур. Добавляйте самый короткий тест, который падает, если
   логика сломается.
3. **Ничего не ломаем молча.** Меняете формат данных или переменную окружения —
   отразите это в README и напишите в PR.
4. **Секретов в репозитории нет** и не будет: только имена переменных, значения
   приходят из окружения.
5. **Никаких новых зависимостей ради пары строк.** Стандартная библиотека и то,
   что уже установлено, — сначала.
6. **Код и идентификаторы — на английском, документация и интерфейс — на
   русском.** Так сложилось исторически, и это удобно.
7. Совместимость с внешними почтовыми сервисами (Яндекс, Mail.ru, VK) проверяйте
   на реальном ящике и пишите в PR, на чём проверяли.

Стиль — как в соседних строках файла. Линтера нет намеренно: PR, который
переформатирует пол-файла, ревьюить невозможно.

## Как проходит pull request

1. Форк, ветка от `main`, осмысленное имя (`feat/imap-presets`, `fix/attachment-name`).
2. Прогоните тесты локально — CI прогонит их же на Python 3.11, 3.12 и 3.13.
3. Откройте PR, заполните шаблон, свяжите с issue.
4. Ревью — по существу и без грубости, см. [Кодекс поведения](CODE_OF_CONDUCT.md).

Отправляя PR, вы соглашаетесь, что ваш вклад распространяется на условиях
[MIT](LICENSE).
