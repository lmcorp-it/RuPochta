What is AI Readiness?

AI coding agents are only as effective as the context they receive. AgentRC measures how AI-ready a repo is across 9 pillars in two categories — Repo Health and AI Setup — and maps the result to a 5-level maturity model. This report is the Measure step in AgentRC's Measure → Generate → Maintain loop.

Each pillar carries an AI relevance rating (High / Medium / Low) so you can tell at a glance which gaps most directly affect Copilot's output and which are general engineering hygiene.

Repo Health Breakdown

Style & Validation AI relevance: medium 0%

What it measures: Linter configuration (ESLint/Biome/Prettier) and type-checking configuration (TypeScript/Mypy).

Why it matters for AI: Lint and type rules are the most explicit form of house style an agent can read. With them in place, Copilot generates code that passes review on the first try; without them, the agent has to guess at conventions and PRs churn on style nits.

Current state: AgentRC found neither a supported lint configuration nor tsconfig.json, pyproject.toml, or mypy.ini (0/2).

Recommendation: Add a repository-level lint configuration and a pyproject.toml or mypy.ini type-check configuration aligned to the Python and frontend code.

Build System AI relevance: high 100%

What it measures: A build script in package.json and CI workflow configuration.

Why it matters for AI: An agent without a build command cannot self-verify. A canonical npm run build (and a CI workflow that mirrors it) lets the agent compile, catch type errors, and iterate before opening a PR — the difference between works on my machine and a clean check run.

Current state: AgentRC found no root application package, so the build-script check was skipped; it did detect CI in .github/workflows (1/1).

Recommendation: Retain CI and document canonical build entry points in README.md; add unified root task metadata only if a repository-wide command is intended.

Testing AI relevance: high 0%

What it measures: A test script and area-scoped test scripts.

Why it matters for AI: Tests are the agent's automated quality gate. With a test script the agent can run TDD loops and prove behaviour; with area-scoped tests it can run only what's relevant and stay fast. No tests = no objective signal for the agent to know when it's done.

Current state: AgentRC evaluated no packaged test-script criterion (0/0) because no root app package was detected. Existing CI runs Python unittest discovery and npm test in rupochta-mcp-server.

Recommendation: Expose canonical root and area-scoped test commands through discoverable project metadata while retaining the existing CI commands.

Documentation AI relevance: high 100%

What it measures: README, CONTRIBUTING, and area-scoped READMEs.

Why it matters for AI: Docs are the agent's primary context source. README explains the stack, CONTRIBUTING explains the process, area READMEs explain local conventions. Repos with rich docs see dramatically better Copilot suggestions because the model is grounded in real intent instead of guessing from filenames.

Current state: README.md and CONTRIBUTING.md are present (2/2); the README also documents project layout, local setup, and tests.

Recommendation: Keep the root guides current and add area-specific READMEs only as components gain independent workflows.

Dev Environment AI relevance: medium 0%

What it measures: A lockfile and .env.example.

Why it matters for AI: A lockfile pins versions so the agent's npm install matches CI. .env.example tells the agent which env vars exist without leaking secrets. Together they make the agent's local runs reproducible and stop it from inventing config that doesn't apply.

Current state: No repository-root package-manager lockfile or .env.example/.env.sample was detected (0/2). .env.dev.example exists for Docker development.

Recommendation: Add a committed dependency lockfile and a sanitized .env.example that lists supported variables and safe defaults.

Code Quality AI relevance: medium 0%

What it measures: Formatter configuration (Prettier/Biome).

Why it matters for AI: A formatter config means the agent's output lands pre-formatted — no diff noise, no review comments about whitespace. Without it, AI-generated PRs trigger style discussions that drown out real feedback.

Current state: No Prettier or Biome formatter configuration was found (0/1). CONTRIBUTING.md notes that a linter is intentionally absent.

Recommendation: Choose and document a formatter configuration, such as biome.json for frontend assets, without forcing unrelated whole-file reformatting.

Observability AI relevance: low 0%

What it measures: OpenTelemetry, Pino, Winston, or Bunyan tooling.

Why it matters for AI: When logging/tracing libraries are visible in the dependency graph, the agent instruments new code with the same patterns instead of console.log. Lower leverage than docs/tests because the agent only needs it for the subset of work that touches runtime instrumentation.

Current state: No supported observability or logging dependency was detected (0/1).

Recommendation: Plan structured logging or tracing with Python-compatible tooling and document the pattern agents should follow.

Security & Governance AI relevance: low 50%

What it measures: LICENSE, CODEOWNERS, SECURITY.md, and Dependabot.

Why it matters for AI: CODEOWNERS routes AI-generated PRs to the right reviewers automatically. SECURITY.md and Dependabot tell the agent how to handle vulnerability reports and dependency bumps. Important for governance, but rarely changes what code the agent writes day-to-day.

Current state: LICENSE and SECURITY.md are present (2/4); .github/CODEOWNERS and .github/dependabot.yml are absent.

Recommendation: Add ownership routing and dependency-update configuration in .github/CODEOWNERS and .github/dependabot.yml.

AI Setup Breakdown

AI Tooling AI relevance: high 0%

What it measures: Custom instructions, MCP servers, agent configs, and AI skills.

Why it matters for AI: The direct interface between repo and AI agents — the highest-leverage pillar in the entire model. A good AGENTS.md is worth more than every other pillar combined: it tells the agent your stack, conventions, build commands, test commands, and review expectations in one place. MCP servers and custom skills extend the agent's reach into your tools.

Current state: No recognized custom instruction, MCP client configuration, custom-agent directory, skills directory, or apm.yml was detected (0/5). The repository includes a rupochta-mcp-server implementation, but no client MCP configuration.

Recommendation: Start with .github/copilot-instructions.md, then add .vscode/mcp.json for the existing MCP server; adopt agents, skills, and APM only where they make workflows repeatable.
